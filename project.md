Как работает сервис
Сейчас сервис «Тарифный калькулятор» использует только суммарный вес груза для расчёта стоимости. Стоимость рассчитывается на данный момент всегда в рублях, груз состоит из упаковок (packages), так как не все грузы можно упаковать в одну большую коробку, также разделение на упаковки оптимизирует загрузку транспортных средств.

Запрос к сервису осуществляется обращением по API:

POST /api/v1/calculate
{
"packages":[
{
"weight": 4564
}
],
"currencyName": "RUB"
}
Вес каждой упаковки указан в граммах. Валюта добавлена для возможности работать с различными валютами в дальнейшем. Сервис суммирует вес каждой упаковки и умножает на стоимость за грамм, но не ниже минимальной стоимости доставки.

Ответ на запрос:

{
"totalPrice": 1643.69,
"minimalPrice": 500.00,
"currencyCode": "RUB"
}
Существуют ограничения:

вес одной упаковки не может быть больше 150 кг;
упаковок не может быть меньше 1;
вес не может быть меньше 0;
валюта — обязательный параметр.
При отправке неверного запроса возвращается ошибка 400.



1. Добавление расчёта на основе объёма
   В пунктах приёма заказов измеряют габариты каждой упаковки и передают их в метод расчёта. Габариты измеряются в миллиметрах:

POST /api/v1/calculate
{
"packages":[
{
"weight": 4564,
"length": 345,
"width": 589,
"height": 234
}
],
"currancyName": "RUB"
}
Ограничения:

высота, длина, ширина не могут быть меньше 0;
один или более габаритов не может быть больше 1 500 мм.
При отправке неверного запроса возвращается ошибка 400.

Алгоритм расчёта стоимости доставки:

Нормализуйте входные данные.
Перед расчётом объёма округлите каждое значение габарита упаковки кратно 50. Для параметров из примера выше должно получиться:

"length": 350,

"width": 600,

"height": 250

Рассчитайте объём кубических метров каждой упаковки с точностью до четвёртой цифры:
Объём = 350 мм * 600 мм * 250 мм / 1_000_000_000 = 0,0525 м3

Умножьте объём всех упаковок на стоимость одного кубического метра. Это значение должно быть в конфигурации приложения для возможности изменения без перекомпиляции кода.
Используя готовый расчёт по весу всех упаковок, сравните стоимость по объёму и весу. Выберите максимальное значение и верните его как totalPrice.
Что оценивается
При передаче одного из параметров габаритов < 0 отвечаем ответом с HTTP-статусом 400.
При передаче одного из параметров габаритов > 1500 отвечаем ответом с HTTP-статусом 400.
Расчёт стоимости учитывает переданные габариты каждой упаковки.
Написаны юнит-тесты на обновлённый алгоритм расчёта стоимости доставки.


2. Использование координат пункта отправки и получения
   До этого мы не использовали учёт пунктов выдачи и отправки, так как работали на небольшой территории, и ставка за вес груза и объём была фиксированной. Теперь для расширения территории работы мы будем учитывать расстояние между пунктами выдачи и получения.

В запрос на расчёт стоимости добавляются координаты пункта отправления (departure)и получения (destination).

POST /api/v1/calculate
{
"packages":[
{
"weight": 4564,
"length": 345,
"width": 589,
"height": 234
}
],
"currencyCode": "RUB",
"destination": {
"latitude" : 73.398660,
"longitude" : 55.027532,
},
"departure" : {
"latitude" : 55.446008,
"longitude" : 65.339151,
}
}
Необходимо проверять входные данные:

Все поля destination и departure должны быть заполнены.
Для каждого из destination- и departure-значения latitude должно быть от 45 до 65 (значения должны быть в конфиге приложения).
Для каждого из destination- и departure-значения longitude должно быть от 30 до 96 (значения должны быть в конфиге приложения).
На основе координат надо посчитать прямое расстояние между пунктами.

Алгоритм расчёта стоимости доставки

Для расчёта расстояния между географическими координатами используйте формулу гаверсинусов с модификацей для антиподов. Прочитайте статью, где описана работа формулы. Рекомендуем взять из неё тестовые данные для проверки правильности вычисления расстояния. Также возможно использовать готовую библиотеку.

Полученное значение расстояния в километрах необходимо использовать для дальнейшего расчёта стоимости доставки.

Базовая стоимость доставки — это доставка, рассчитанная на основе веса и объёма.

За каждые 450 км взимается базовая стоимость на основе веса и объёма, но не менее чем за 450 км. Результат округляется до 1 копейки в большую сторону.

Какие бизнес-объекты содержит ваше приложение и какие у них ограничения?
В процессе работы над кейсом появляются новые бизнес-термины: габариты упаковки, объём, географическая координата, расстояние.

У каждого есть ограничения, которые можно применять при валидации создания. Пример такого ограничения: объём не может быть меньше нуля.

Например, габариты могут выглядеть как OuterDimensions:

/**
* Габариты
*
* @param length Длина
* @param width Ширина
* @param height Высота
  */
  public record OuterDimensions(
  Length length,
  Length width,
  Length height
  ) {
  }
  Lenght — это класс, определяющий длину. В конструкторе OuterDimensions вы можете проверить, что ни одна из длин не нарушает ограничения, используя, например, Canonical Constructor в record-классе.

public OuterDimensions {
var maxLength = Length.fromMillimeter(MAX_LENGTH_DIMENSION);
if (width.isLongerThan(maxLength) {
throw new IllegalArgumentException(
"width is longer than maxLength");
}
}
Метод isLongerThan — это часть класса Length. Класс самостоятельно сравнивает себя с подобными ему, после того как вы напишете этот метод.
